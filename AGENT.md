# WordPress Plugin Development Specification: Custom LD Schema

Develop a WordPress plugin named **Custom LD Schema** that allows administrators to assign custom JSON-LD schema markup to any supported post type while ensuring compatibility with popular SEO plugins such as Yoast SEO, Rank Math, SEOPress, All in One SEO, and similar plugins.

## Plugin Requirements

### Plugin Name

**Custom LD Schema**

---

# Core Features

## 1. Custom Field (Meta Box)

When the plugin is activated, add a meta box titled **LD Schema** to the post editor.

The meta box must be available for all enabled post types.

Users should be able to paste either of the following:

### Option 1

A complete script tag:

```html
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@graph": [
    {
      ...
    }
  ]
}
</script>
```

### Option 2

Raw JSON-LD only:

```json
{
  "@context": "https://schema.org",
  "@graph": [
    {
      ...
    }
  ]
}
```

The plugin should automatically detect whether the input includes the `<script>` wrapper.

---

# 2. Frontend Output

If a custom schema exists for the current page, output exactly one schema block in the page source using the following format:

```html
<script
    type="application/ld+json"
    id="ld-custom-schema"
    class="ld-custom-schema">
{
  "@context": "https://schema.org",
  "@graph": [
    ...
  ]
}
</script>
```

Even if the user pasted the complete `<script>` block, the plugin should strip the outer `<script>` tags before saving or outputting, ensuring the frontend always uses the standardized format above.

---

# 3. SEO Plugin Compatibility

The plugin must be compatible with major SEO plugins, including but not limited to:

* Yoast SEO
* Rank Math
* SEOPress
* All in One SEO
* The SEO Framework
* Other plugins that output JSON-LD

### Required Logic

If a page has a custom schema saved:

* Prevent any existing JSON-LD schema generated by SEO plugins from being output.
* Output only the custom schema.

The goal is:

* One JSON-LD script per page when custom schema exists.
* No duplicate Schema.org markup.
* Avoid conflicts with SEO plugins.

Use official WordPress hooks and plugin filters whenever possible rather than fragile output buffering.

---

# 4. Post Type Support

The plugin must support any public post type.

Examples include:

* Posts
* Pages
* Products (WooCommerce)
* Portfolio
* Services
* Events
* Downloads
* Custom Post Types created by themes or plugins

---

# 5. Admin Settings Page

Create a top-level admin menu named:

**LD Schema**

Inside this page, display a list of all public post types with checkboxes.

Example:

```
☑ Posts
☑ Pages
☐ Products
☐ Portfolio
☐ Services
☐ Events
☐ Downloads
```

Requirements:

* All public post types should be listed automatically.
* "Posts" and "Pages" must be enabled by default.
* Administrators can enable or disable the meta box for each post type.
* Save settings using the WordPress Settings API.

---

# 6. Validation & Sanitization

When saving:

* Remove surrounding `<script>` tags if present.
* Store only the JSON content.
* Preserve formatting and indentation.
* Do not modify valid JSON-LD.

When outputting:

* Wrap the stored JSON in the standardized script tag.
* Escape output appropriately for security.
* Do not double-encode JSON.

---

# 7. Performance

* Do not load unnecessary scripts or styles.
* Load admin assets only on relevant screens.
* Output schema only when custom schema exists.
* Follow WordPress coding standards and best practices.

# Expected Behavior

### If no custom schema is saved:

* SEO plugins continue to output their normal JSON-LD.

### If custom schema is saved:

* Suppress JSON-LD generated by supported SEO plugins whenever possible.
* Output only the custom schema in the following format:

```html
<script type="application/ld+json" id="ld-custom-schema" class="ld-custom-schema">
...
</script>
```
